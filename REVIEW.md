# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Returns static `{"status": "ok"}` without checking if MongoDB is alive. Specification requires returning 503 when MongoDB does not answer. | Stop MongoDB service; `GET /health` still returns HTTP 200 instead of 503. | Added `db.command("ping")` wrapped in try/except; raises `HTTPException(503, "Database unavailable")` on connection failure. |
| 2 | `list_attendance` (lines 144-147) | Loads all matching documents into memory with `list(db.attendance_logs.find(q))` and sorts in Python. Fails with OOM/timeout on a 100k-document dataset. | Benchmark query time with 100,000 documents; response hangs or exceeds memory limit. | Replaced in-memory sorting and pagination with MongoDB cursor methods: `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` backed by compound index. |
| 3 | `list_attendance` (line 145) | Sorts only by `date` descending, omitting the required secondary sort by `emp_code` ascending. | Query attendance page where multiple records share the same date; order of `emp_code` is unstable/non-deterministic. | Added secondary sort key `("emp_code", 1)` to MongoDB query. |
| 4 | `list_attendance` (lines 136-142) | Does not validate that `date_from <= date_to`. The specification requires returning 422 if `date_from > date_to`. | Pass `date_from=2026-07-10&date_to=2026-07-05`; returns empty 200 instead of 422. | Added validation raising `HTTPException(422, "date_from must be on or before date_to")` when `date_from > date_to`. |
| 5 | `list_employees` (line 93) | Pagination skip formula is `skip = page * page_size`. For page 1, `skip = 20`, completely skipping the first page of results. | Request `GET /employees?page=1&page_size=20`; records 1-20 are missing and records 21-40 are returned. | Corrected formula to `skip = (page - 1) * page_size`. |
| 6 | `list_employees` (line 94) | `total` count calculates `count_documents({})` on the entire collection, ignoring the `department` filter. | Pass `GET /employees?department=Engineering`; `total` reports total company headcount rather than Engineering headcount. | Updated count to `db.employees.count_documents(q)` to reflect the filtered set. |
| 7 | `list_employees` (line 95) | Missing mandatory sort by `emp_code` ascending as required by OpenAPI contract. | Query `GET /employees`; order is natural storage order rather than sorted by `emp_code`. | Added `.sort("emp_code", 1)` to the MongoDB query cursor. |
| 8 | `create_employee` (lines 79-84) | Check-then-insert race condition. If two requests with the same `emp_code` arrive simultaneously, both pass `find_one` and create duplicate employees. | Send concurrent identical `POST /employees` requests; both return 201 and corrupt uniqueness. | Created unique index on `employees.emp_code` at startup; wrapped `insert_one` to catch `pymongo.errors.DuplicateKeyError` and raise HTTP 409. |
| 9 | `create_employee` (lines 82-85) | `created_at` is set as a naive datetime and returned in response as ISO string/datetime instead of epoch milliseconds integer as required by OpenAPI. | Response schema validation fails against OpenAPI `EpochMillis` schema. | Stored as UTC BSON datetime in MongoDB; serialized to epoch milliseconds integer (`int(dt.timestamp() * 1000)`) in API response. |
| 10 | `EmployeeIn` model (lines 53-60) | Missing input validations: `emp_code` regex (`^EMP\d{4,6}$`), `shift_start != shift_end`, email pattern, string length bounds. | Send invalid `emp_code="BAD1"` or `shift_start="09:00"&shift_end="09:00"`; request succeeds instead of returning 422. | Added Pydantic field regex patterns, length constraints, and model validator ensuring `shift_start != shift_end`. |
| 11 | `punch_in` (lines 104-118) | Check-then-insert race condition. Simultaneous punch-in requests for the same employee and date both succeed instead of yielding exactly one 201 and one 409. | Send two concurrent punch-in requests for same employee and date; both return 201. | Created compound unique index on `attendance_logs(emp_code, date)` at startup; catch `DuplicateKeyError` and raise HTTP 409. |
| 12 | `punch_in` (line 101) | Does not check if `emp_code` exists before punching in. Accessing `emp["shift_start"]` on line 113 throws `TypeError` (HTTP 500) if employee is missing. | Send punch-in for non-existent `EMP9999`; server crashes with 500 instead of returning 404. | Check if `emp` is None and raise `HTTPException(404, "Employee not found")`. |
| 13 | `punch_in` & `compute_late_minutes` (lines 33-37, 102-103) | Attendance date calculation does not handle overnight shifts (R1), and subsecond milliseconds are not truncated to whole seconds before calculation. | Punch-in at 01:00 for an overnight shift (22:00 - 06:00); date is attributed to current day rather than previous day. | Implemented R1 overnight shift logic where punch-in earlier than `shift_end` is attributed to the previous calendar day; truncated instants to whole seconds. |
| 14 | `compute_late_minutes` (lines 35-37) | Grace period logic performs integer minute division before comparison: `int((punch_in - start).total_seconds() / 60) > 10`. 09:40:30 on a 09:30 shift has 10.5 mins, truncates to 10, and evaluates `10 > 10` as False (returns 0 instead of 10). | Punch in at 09:40:01 for a 09:30 shift; returns 0 minutes late instead of 10 minutes late. | Calculated total elapsed seconds strictly greater than 600 seconds (`> 10 * 60`), then set `late_minutes = int(elapsed_seconds // 60)`. |
| 15 | `compute_work_hours` (lines 40-41) | Uses Python built-in `round()`, which applies banker's rounding (round-to-even) instead of round-half-up required by R4 and R8. | Work hours calculation for 2.675 hours rounds down to 2.67 instead of 2.68. | Used Python `decimal.Decimal` with `ROUND_HALF_UP` to round work hours to 2 decimal places. |
| 16 | `compute_overtime` (lines 44-48) | Counts any minutes past `shift_end` (e.g. 10 minutes $\rightarrow$ 10), ignoring Rule R3 which specifies overtime is counted only if >= 30 minutes; otherwise 0. Also fails on overnight shifts. | Punch out 15 minutes after shift end; returns 15 minutes overtime instead of 0. | Enforced R3 threshold: return `minutes` if `minutes >= 30` else `0`. Handled overnight shifts crossing midnight. |
| 17 | `punch_in` & `list_attendance` (lines 119, 149) | Injects `id: str(_id)` into the response, leaking MongoDB internal ObjectId. OpenAPI schema explicitly defines records addressed by `(emp_code, date)` without any `id` field. | Inspect JSON response of punch-in or list; extra `id` field violates OpenAPI schema contract. | Removed `id` field injection; formatted response strictly matching `AttendanceRecord` schema. |
| 18 | `PunchInIn` model (lines 63-66) | Accepts any string for `status` (including ABSENT or invalid values), and accepts non-epoch-millisecond numbers, floats, or strings for `punched_at`. | Send `punched_at=1783312500` (seconds instead of ms) or `status="ABSENT"`; request accepted instead of returning 422. | Restricted `status` enum to `PRESENT`, `WFH`, `ON_DUTY` only. Added strict `EpochMillis` validation (integer between 100000000000 and 4102444800000). |
| 19 | Application initialization (lines 18-28) | No database indexes created at application startup. Grader seeds database directly with only `_id` index. | Explain queries or query large dataset; operations perform full collection scan (`COLLSCAN`). | Implemented FastAPI lifespan context manager to create all necessary unique and compound indexes idempotently at startup. |

## What we examined and decided was NOT a defect:

1. **Environment variable fallback in `MongoClient(os.getenv(...))`**: Using `os.getenv("MONGO_URI", "mongodb://localhost:27017")` is correct because it allows local testing while ensuring real injected environment variables take precedence, satisfying the environment contract.
2. **Absence of a synthetic primary key `id` in attendance records**: Attendance records are designed to be addressed by the natural key `(emp_code, date)` as explicitly defined in Section 5 of `PROBLEM_STATEMENT.pdf` and `DATA_MODEL.md`.
